# MORIKAWA RYOTA Portfolio

森川亮太のポートフォリオサイトです。HTML・CSS・JavaScriptで構成されており、作品情報から静的な作品一覧と詳細ページを生成します。

## ファイル構成

| パス | 内容 |
| --- | --- |
| `index.html` | トップページ・代表作 |
| `about.html` | プロフィール |
| `works.html` | 作品一覧（生成ファイル） |
| `works/<作品フォルダ>/index.html` | 作品詳細（生成ファイル） |
| `works/<作品フォルダ>/img/` | 公開用の作品画像 |
| `data/instagram-works.json` | 作品情報の管理データ。手動追加作品もここで管理 |
| `scripts/import-instagram-works.py` | 取得データの取り込み・HTML生成 |
| `css/`・`js/`・`assets/` | スタイル・動作・共通素材 |
| `CNAME` | 公開サイトのカスタムドメイン設定 |

## 公開リポジトリについて

このリポジトリにコミットした文章・画像・JSONは、誰でも閲覧・取得できます。サイトに表示されないJSONの項目も公開されます。

- 掲載可能な作品・画像・クレジットのみを追加してください。画像を追加する前に、位置情報など公開不要なメタデータも確認してください。
- パスワード、アクセストークン、Cookie、セッション情報、非公開の連絡先、未公開案件の情報は保存しないでください。
- クロール時の一時ファイル、ダウンロード元のローカルパスを含む生のエクスポート、認証情報はリポジトリ外で管理してください。
- ファイルを削除してもGitの履歴に残る場合があります。コミット前に差分を確認してください。

## 基本の更新方法：Instagram更新ごとに取得する

Instagramに作品を投稿・更新した際に、その都度対象投稿をクロールし、公開用の画像と作品情報を取得してサイトへ反映します。

**現状、このリポジトリにはInstagramのクローラーや定期実行の設定はありません。** 以下はクロールを別途行い、その結果を既存の生成スクリプトに渡す運用手順です。サイトの閲覧時にInstagramへアクセスする仕組みではありません。

### 1. 投稿・画像を取得する

対象投稿について、投稿URL、投稿日、本文、カルーセル内の画像を取得します。動画投稿は、サイト掲載用のカバー画像を用意します。現在の生成スクリプトは画像の掲載に対応しており、動画ファイルの埋め込みは行いません。

取得時には、新規投稿だけでなく既存投稿の本文や画像の更新も確認してください。同じ投稿URLは同一作品として扱い、重複追加を避けます。取得できない場合は既存データを残して、取得できた範囲を確認してから反映してください。

### 2. 取得データを作品データへ反映する

通常の追加・更新では、`data/instagram-works.json` の `posts` に対象作品を追加、または既存作品を更新し、画像を `works/<作品フォルダ>/img/` に保存します。各項目の形式は後半の手動追加例と共通です。

- Instagram由来の `id` は `instagram-<投稿のショートコード>` とします。
- `source` に公開投稿のURLを設定します。
- `publishedAt` はタイムゾーン付きの日時にします。
- `images` は表示したい順に並べます。先頭画像が作品一覧のサムネイルになります。
- `retrievedOn` を実際の取得日に更新します。
- `posts` は `publishedAt` の新しい順に並べます。通常の再生成では自動で並べ替えられません。

既存作品の `folder` は、リンクを維持するため原則そのまま使用します。Instagramの投稿削除を理由にサイトからも削除する場合は、対象データと公開画像を確認して個別に削除してください。

#### 生のエクスポートから取り込む場合

スクリプトの `--export` は、次のようなJSON配列を受け取ります。例のURL・日時・パスは実際に取得した値に置き換えてください。

```json
[
  {
    "url": "https://www.instagram.com/p/POST_SHORTCODE/",
    "date": "2026-09-30T10:00:00Z",
    "caption": "【Still work】\n作品タイトル\n撮影を担当しました。",
    "files": [
      {
        "source": "https://example.com/downloaded-image.jpg",
        "path": "/tmp/portfolio-import/01.jpg",
        "cover": false
      }
    ]
  }
]
```

`detailCaption` がある場合は `caption` より優先されます。`files[].source` は取得元画像のURLで、URLのパス末尾のファイル名を使って画像の重複を判定します。`files[].path` はダウンロード済み画像のローカルパスです。

```bash
python3 scripts/import-instagram-works.py --export /tmp/portfolio-import/export.json
```

**このコマンドは既存JSONへの差分追加ではなく、渡したエクスポートで作品データ全体を置き換えます。** 新規投稿だけを渡すと、過去作品や手動追加作品が一覧から外れます。利用する場合は、事前に管理JSONをリポジトリ外へバックアップし、全対象投稿を含むエクスポートを渡してください。取り込み後、手動追加作品と独自に修正した項目をバックアップから戻し、再生成します。

取り込みではタイトルとカテゴリを本文から推定するため、結果を確認・修正してください。取得日の `retrievedOn` は現在のスクリプトでは固定値なので、実際の取得日に書き換えてください。JPEG以外の入力画像の変換にはmacOSの `sips` を使用します。他の環境ではあらかじめJPEGに変換してください。

### 3. HTMLを再生成する

リポジトリのルートで実行します。Python 3が必要です。JPEG画像を用意した通常の再生成には、追加のPythonパッケージは必要ありません。

```bash
python3 -m json.tool data/instagram-works.json > /dev/null
python3 scripts/import-instagram-works.py
```

`works.html` とJSONに含まれる各作品の `index.html` が再生成されます。生成HTMLを直接編集すると次回の生成で上書きされるため、作品情報はJSONで修正してください。トップページの代表作は自動更新されないので、変更する場合は `index.html` のリンク・画像・表示名も編集します。

### 4. 表示と公開差分を確認する

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

ブラウザで `http://localhost:8000/` を開き、作品一覧、カテゴリの絞り込み、詳細ページ、画像順、元投稿へのリンクを確認します。スマートフォン幅でも画像や文章の表示を確認してください。確認が終わったら `Ctrl+C` でサーバーを停止します。

```bash
git status --short
git diff --stat
git diff -- data/instagram-works.json works.html
```

追加画像も確認したうえで、更新したJSON・画像・生成HTMLをコミットし、公開に使用しているブランチへ反映します。公開後も新しい作品の表示を確認してください。

## Instagramに記載のない作品を追加する

Instagramへの投稿がない作品も、同じ管理JSONに追加して掲載できます。以下の手順では、作品情報と公開用JPEGを手動で用意します。

### 1. 作品画像を配置する

既存作品と重複しないフォルダ名を決め、画像を表示順に配置します。

```text
works/
  sample-project/
    img/
      01.jpg
      02.jpg
```

`index.html` は次の再生成で作成されます。画像のピクセル寸法を確認し、JSONの `width`・`height` に実寸を設定してください。

### 2. 管理JSONに作品を追加する

`data/instagram-works.json` の `posts` 配列に、次の形式で1作品分のオブジェクトを追加します。値はすべて掲載する作品に合わせて置き換えます。

```json
{
  "id": "manual-sample-project",
  "folder": "sample-project",
  "title": "作品タイトル",
  "categories": ["photo"],
  "publishedAt": "2026-09-30T12:00:00+09:00",
  "source": "https://example.com/projects/sample-project",
  "sourceLabel": "作品の公式ページを見る",
  "caption": "作品の説明文。\n担当した内容や公開可能なクレジットを記載します。",
  "images": [
    {"file": "img/01.jpg", "width": 1440, "height": 960, "cover": false},
    {"file": "img/02.jpg", "width": 1440, "height": 960, "cover": false}
  ]
}
```

| 項目 | 設定方法 |
| --- | --- |
| `id` | 他作品と重複しない識別子。手動作品には `manual-` を付ける |
| `folder` | `works/` 内の作品フォルダ名と完全に一致させる。`/` や `..` を含めない |
| `title` | 公開する作品名 |
| `categories` | `photo`・`movie`・`production-staff` のいずれか。複数指定も可能 |
| `publishedAt` | 一覧の並び順・詳細の日付に使用する、タイムゾーン付き公開日時 |
| `source` | 公開済みの公式作品ページなどのURL |
| `sourceLabel` | 外部リンクの表示文言。省略するとInstagram向けの文言になるため手動作品では指定する |
| `caption` | 公開する説明文。改行は `\n` で記述 |
| `images` | 1枚以上の画像。`file` は作品フォルダからの相対パス |
| `cover` | 取得画像が動画カバーかどうかの情報。現在の一覧サムネイルはこの値によらず先頭画像を使用 |

現在の生成スクリプトでは `source` が必須で、外部リンクは必ず表示されます。公式作品ページがない場合は、作品を紹介する公開済みの関連ページを指定してください。リンクなしで掲載したい場合は、先に生成スクリプトをリンク省略に対応させる必要があります。

詳細ページではメンション・ハッシュタグ・絵文字が除去されます。必要な担当者名やクレジットは通常の文章として記述してください。元のJSONには入力した内容がそのまま残るため、公開不要な情報は初めから入力しないでください。

### 3. 再生成して確認する

`posts` を日時の新しい順に並べ、前半と同じ生成・表示確認の手順を実行します。

```bash
python3 -m json.tool data/instagram-works.json > /dev/null
python3 scripts/import-instagram-works.py
```

画像ファイル、管理JSON、生成された作品詳細HTML、`works.html` をまとめてコミットします。次回Instagramを取り込む際も、手動作品を管理JSONに残してください。特に `--export` を使う場合は、取り込み後の復元が必要です。

作品を削除する場合は、JSONから対象作品を取り除き、再生成したうえで、不要になった `works/<作品フォルダ>/` も削除します。再生成だけでは古い作品フォルダは削除されません。トップページなどからリンクしている場合は、その参照も更新してください。
